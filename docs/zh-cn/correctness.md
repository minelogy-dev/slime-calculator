# 正确性：目标、证据、以及明确排除的东西

正确性被收敛成**三条可判定的目标**，每条都有对应的、可复现的证据。除此之外的东西要么
**已被检查**（0 UB），要么**明确排除在范围外**（并发/时序）。

---

## 0. 正确性目标

| # | 目标 | 含义 |
|---|---|---|
| **A** | **输出不重不漏** | 输出的每一行都对应一个真实存在且满足条件的矩形；每个满足条件的矩形都**恰好输出一次** |
| **B** | **判定规则 = wiki 的 MC 原始算法** | 某个区块是不是史莱姆区块，等于 Minecraft wiki 那段 Java 的判定 |
| **C** | **接口语义 = 文档** | CLI/README 定义的坐标（×16）、阈值（`count >= threshold`）、排序（`--sort`）、扫描区间按 256/256 向上补齐 —— 与文档逐条一致 |

「不重不漏」拆成两个可独立检查的断言：
* **不重**：输出里 `(x, z)` 唯一（结构不变式里的 `dup=0`）；
* **不漏**：输出的集合与独立 oracle 算出的集合**相等**（不是包含、不是抽样）。

**而且它是被证明的，不只是被测过的** —— 见 `docs/zh-cn/correctness-proof.md`：
融合核与回退核的列/行/块/chunk 四级切分、滑动窗口不变式、发射门、登记上界
共 14 条引理，逐条对着 `src/slime_main.cu` 的现行代码给出证明。

## 1. 目标 B：判定规则 —— 外部权威对拍

`tools/mccrosscheck.sh`：

1. 从 `docs/en-us/index.md` **逐字抽取**那个 ```java 代码块（抽完做哈希校验，不是重打一遍），
   并要求它确实定义了 `CheckSlimeChunk`；
2. 交给**真正的 JVM** 编译执行（OpenJDK 21.0.12 与 26.0.2 各测过一遍，两版给出同一个集合）；
3. 程序侧用 **1×1 窗口 + thr 1** 跑同一区域 —— 此时它的输出集合**恰好等于史莱姆区块集合**；
4. 两边都按 `LC_ALL=C` 排序后逐字节比对。

**实测：区域 `[-512,511]²`（1,048,576 个区块）上 104,722 个史莱姆区块完全一致。**

这个检查有牙齿：把 `slimeBallotSlow` 里的 Java 拒绝重抽删掉（`src/test.cpp` 已证明最多重抽一次，
删掉看起来无害），它会 FAIL 并**直接指出违规的那一格 `5,7`**。

这层检查**必须真跑 JVM**，没有缓存摘要可退：判定集只是种子、区域与那段 Java 的函数，
一份离线记下的计数/sha256 无法自证是否已经过期，规范漂移后它仍会报 PASS。
所以脚本检测不到 JDK 时直接以 rc=2 退出，而不是拿旧摘要放行。

## 2. 目标 A：不重不漏 —— 与独立 oracle 全量比对

oracle（`tools/oracle.c`）从 Java 规范直译，与 `src/slime_main.cu` **零共享代码**；
小区域上它还**同时用暴力逐格求和**（`O(sizeX*sizeZ)`/候选）复算一遍，两种方法不一致就
拒绝给出期望值 —— 于是「程序 vs oracle」这条链的末端是朴素求和，而不是另一个聪明算法。

| 检查 | 规模 | 结果 |
|---|---|---|
| `tools/fullcheck.sh` 穷举 soak | **21372** 项 | **全部 PASS，0 失败** |
| ├ P1 穷举 `sizeX` 1..255 × `sizeZ` 1..32 × 3 种子 × 6 编译变体 | 20628 | PASS |
| ├ P2 几何边界（宽 1..4096 / 高 1..65537 / 坐标 ±2e6 / 6 种 rect） | 566 | PASS |
| ├ P3 溢出重试 × 落盘归并 × `--sort on/off` | 152 | PASS |
| ├ P4 全图级区域：行不变式 + 300 点随机探针（双向抓多报与漏报） | 6 | PASS |
| └ P0/P5 健全性、负向对照、确定性、单调性 | 20 | PASS |
| `tools/quickcheck.sh`（约 10 秒；本机专用，未随仓库发布） | 26 项 | PASS |
| `tools/verify.sh`（与冻结参考逐字节一致） | 46 项 | PASS |

每一项都比对**完整行集合**：既抓多报（不重），也抓漏报（不漏）。

**低概率分支要专门构造输入**：Java 拒绝路径概率 ~4e-9，随机区域里几乎不存在「能区分对错」的格子。
已加 **5 个定向用例、跨 3 个种子**，且**两个失败方向都覆盖**（跳过重抽既可能多报、也可能漏报）。
可复现地重新搜索：

```bash
./build/oracle --scan-reject --seed S --x0 .. --z0 .. --x1 .. --z1 ..
# fast != correct 的格子才算「有区分度」；密度约 4e-9，8.6e9 格才出几个
```

## 3. 目标 C：接口语义 —— 与文档一致

文档定义的四条，逐条都有检查兜住：

| 文档约定 | 检查 |
|---|---|
| 输出世界/方块坐标（区块 ×16） | 每行断言 `x % 16 == 0 && z % 16 == 0` |
| 报告 `count >= threshold` 的矩形 | 每行断言 `count >= threshold`；阈值边界用 0 / 1 / 最大值 / 最大值+1 单独测 |
| `--sort=on` 输出 `(x,z)` 字典序 | 逐行断言严格递增；`--sort=on/off` 必须是同一多重集 |
| 扫描区间按 256/256 向上补齐 | 断言程序自报的 `Global range` 等于按文档规则算出的区间，且**包含请求区间** |

另外把「请求区间 ⊆ 扫描区间」单独断言 —— 这条挡住「少扫一点」这类错误。

## 4. 0 UB

编译器与驱动保持 C++ 语义属于编译器厂商的义务；本程序需要保证的是自己不依赖未定义行为。
因此这一节只确认一件事：代码里没有 UB。

**静态核对**（代码里所有 UB 敏感构造，逐个确认是有定义的）：

| 构造 | 为什么不是 UB |
|---|---|
| `(uint8_t)(a - b)` 前缀和回绕 | 无符号算术按 2^N 取模，标准保证 |
| `ux * ux * 4987142u` 等 32 位乘法回绕 | 同上，全程 `uint32_t` |
| `(int32_t)(...)` 窄化转换 | 实现定义（GCC/Clang = 二进制补码回绕），不是 UB；且与 Java `(long)(int)` 语义相同 |
| `(sizeX >= 32) ? 0xFFFFFFFFu : ((1u << sizeX) - 1u)` | 三元运算符保证 `sizeX == 32` 时**不求值**右支，移位量恒 < 32 |
| `d_pool` 各子缓冲按 256B 对齐后再 `reinterpret_cast` | 对齐满足要求，无 UB |
| 环形缓冲读取 | 整块预清零 + `d_baseX` 尾部 `memset`，无未初始化读 |
| 有符号溢出 | 设备端与主机端都没有：坐标界 ±2e6，`z*16` ≤ 3.2e7，计数 ≤ 255×32 |

## 5. 明确排除在范围外的部分

* **并发与时序**：结果池的排序线程、落盘、写盘线程、以及由 `atomicAdd` 决定的行序 ——
  输出按**多重集**比较，**不承诺顺序**。这是设计选择，不是未验证项。

## 6. 一句话总结

| 目标 | 状态 |
|---|---|
| A 输出不重不漏 | **已证明**（`docs/zh-cn/correctness-proof.md`，14 条引理，两个计算核都覆盖）**且验证过**：21372 项穷举 + 26 项快速 + 46 项位精确，全部与独立 oracle 全量比对 |
| B 判定规则 = MC 原始算法 | **验证过**：真 JVM 跑 `docs/en-us/index.md` 里 wiki 原始 Java，104,722 区块一致 |
| C 接口语义 = 文档 | **验证过**：四条约定各有断言 |
| 0 UB | **静态逐条核对**：代码里所有 UB 敏感构造逐个确认有定义 |

目标 A 是**证明的**：两个计算核（融合核 `sizeX ≤ 32`、回退核 `sizeX > 32`）的切分与窗口
不变式都有归纳证明（`docs/zh-cn/correctness-proof.md`），只依赖一个假设 —— 编译器与驱动保义，
而那以 0 UB 为前提。目标 B/C 与 0 UB 是**验证的**：外部权威对拍、逐条断言、静态核对；
「验证过」指在这些矩阵上没有找到反例，矩阵之外的部分没有被测过。
